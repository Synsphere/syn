## Search narrowly and exclude generated storage

Kieran, 2 November 2026: do not repeatedly scan drives for routine context. Be intelligent about search scope and exclude huge build/cache subfolders. Apply across chats, agents and automations; this limits discovery cost without preventing useful searches of the owning project's source.

- Start with the supplied path, known task receipts, current project instructions, maintained tool registry and exact owning repository. Prefer direct reads and filename discovery within a named small subtree before searching file contents. Never start a routine lookup at a drive root, all of My Songs, all repositories/worktrees, or the whole Tools/Reports tree. Widen only to a specific likely location after a bounded miss; a genuinely broad inventory requires an explicit task need or Kieran's request.
- Exclude generated storage before recursion: dependency/package stores (`node_modules`, `.pnpm-store`, `.uv-cache`), virtual environments (`.venv`, `venv`), `.git` internals, build/output trees (`build`, `dist`, `target`, `obj` and actual generated `bin` directories), caches/test temp trees (`.cache`, `.tmp`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `__pycache__`), model weights/caches (`models`), generated media/render intermediates, and unrelated copied repositories/worktrees. Search such material only when that exact material is the subject, in its smallest relevant subtree. Never read a whole binary/media/model tree to locate a document or setting.
- Avoid blanket `--hidden`. An explicit positive `rg -g/--glob` can override ignore rules: put generated-storage exclusions after inclusion globs and verify the intended scope. Restrict content searches to relevant text/source types, sensible file sizes and a small thread count when storage is contended. `rg -m` limits matches per file, not total work; `Select-Object -First`, output/token limits and `yield_time_ms` do not impose a reliable scan deadline.
- Keep every launched search owned until it exits or is cancelled. Retain and inspect the full command result (`session_id`, `exit_code`, output), rather than printing only `r.output`. A completed orchestration cell is not proof that its child command completed. If a command yields, poll it or cancel the actual owned process/tree and verify exit before widening the search or handing off. Stopping an outer `functions.exec` cell alone is not process-cleanup evidence. No unattended/background discovery scans.
- Do not inspect `.codex-relocated-home`, sessions, browser profiles, caches or private application stores as generic context search roots. Exact saved command/session records may be read in bounded form for an explicitly requested forensic diagnosis; this exception does not permit recursive history scans or browser-session inspection.
- Reuse retained findings instead of rescanning. If the bounded route does not locate the answer, state the precise missing path or evidence and continue independent work. A saved policy is not proof that already-running chats have adopted it or that a runtime cancellation defect is fixed.
